## Files, folders and metadata

Personal uploads still wrap DEKs with the account RSA sharing public key (`encryptFile`, `encryptFileChunked`); organization/team uploads use a raw Space key and a GCM wrap IV. The ProductSpaceKey-derived metadata key protects personal names, tags and the standardized metadata object. This is a genuine transition from the old Vault, not a finished single file-encryption format.

The main browser path chooses opaque object names and encrypts sensitive display metadata. Server presign accepts a caller-provided `fileName`, and folders use `${prefix}${name}/` while `encryptedDisplayName` is optional. Thus opaque names are a browser convention, not an enforced server contract. Personal completion also accepts `isEncrypted:false`. **FIX F08** for all API clients without falsely claiming the normal browser deliberately sends plaintext file bodies.

`objects/update-metadata` still writes plaintext `description` and `googlePhotosUrl`. Share bundle titles are plaintext `bundleName`. Content type/media category, timestamps, aspect ratio, size, folder relationships and share recipients also remain visible. Some are operational metadata; descriptions and user-authored titles exceed a minimal routing requirement. **MIGRATE F25** to encrypted metadata, and explicitly document any retained metadata leakage.

The legacy metadata decoder accepts a format that embeds the AES key alongside ciphertext. This remains reachable through `decryptMetadataString` and the crypto worker. New writes use the newer key-based format, so this is not proof that current uploads embed their key. Existing legacy rows, if present, are not confidential to their storage server. **INVESTIGATE F24** population and migrate client-side; do not remove the reader blindly.

## Large uploads, retries and memory

Drive has two nested orchestration layers: `UploadEngine` queues/retries, while UploadContext performs XHR retries, chunk scheduling, lifecycle listeners, journals and finalize requests. The generic engine has only two tests. Extraction should move the concrete Drive adapter into a browser file-runtime package after its behaviors are covered, not replace the working retries wholesale.

`encryptFileChunked` reads the complete file with `arrayBuffer()` and accumulates encrypted chunks. “Chunked” describes encryption/storage layout, not bounded-memory input processing. Five concurrent Drive jobs amplify this memory footprint. Photos separately uses whole-blob encryption with three jobs. **FIX** by processing bounded slices/streams, measuring memory, and retaining per-file authentication failure handling.

Resume records omit Space ID, wrap mode/version/IV, and resumed complete requests do not restore them. **FIX F17** before advertising workspace resume. The journal also stores the actual filename despite comments describing encrypted persistence; lock does not delete that journal. **MIGRATE** display metadata into an encrypted journal record.

`markChunkComplete` performs read/modify/write without a Dexie transaction; concurrent completion updates can lose journal entries. The remote upload-status reconciliation mitigates some retry inefficiency, but does not make the local journal atomic. **FIX** with transactional updates and interrupted-upload tests.

## Space permissions, quotas and deduplication

`assertObjectAccess` checks both action and Space. Several generic endpoints instead use only `requireAccessContext` and bucket filters, with no `assertScopeAction`. Since shared regional bucket membership is not write permission, guests can reach presign/finalize and some mutation/purge paths. **FIX F07** at the server; disabled UI controls are insufficient.

Completion HEAD checks existence but does not use returned `ContentLength` to establish billed bytes. Chunk totals add caller-supplied `chunk.size`. Derived thumbnail/preview bytes are not consistently included. **FIX F11** with an upload manifest and authoritative byte sizes, including retry and concurrent finalization cases.

Fingerprint dedup lookup is `{bucketId, syncContentFp, deletedAt...}` without `spaceId`; the physical bucket is shared. A matching fingerprint in another account can affect results even though server-side uniqueness is scoped by Space. **FIX** the query scope. A per-user HMAC reduces accidental collision but is not an authorization check; the API accepts client-supplied fingerprint strings.

Regional routing is substantially implemented: AccessContext carries region, the upload paths pass it explicitly, and token-served downloads reverse-resolve bucket name. The leftover AsyncLocalStorage default must not be treated as automatically set. **KEEP** explicit region propagation; **FIX F29** configuration fallbacks and deployment omissions.

## Sharing, editing and versions

Public sharing generates a random key in the browser, puts it in the URL fragment, rewraps the DEK and re-encrypts name/type/thumbnail under the share key. The fragment is not part of an HTTP request. Direct sharing wraps material for recipients' RSA public keys. Server passwords/access lists/expiry constrain distribution of ciphertext; they are not substitutes for the client-held share key. **KEEP** those distinct boundaries.

Role policies and direct-share save authorization have meaningful route tests. A recipient can still retain already-decrypted content after revocation; access revocation is prospective. No public-key transparency/fingerprint-verification workflow was found to authenticate recipient keys against a malicious key-directory server. **INVESTIGATE** that threat model before claiming malicious-server-resistant sharing.

Office `applyContentUpdate` reserves quota, writes a fresh encrypted blob, and updates by expected revision; ten retained versions include a pinned spreadsheet original. This is useful working logic. However, a database exception after blob creation is not a durable cleanup record, and version deletion shares the fail-open deletion helper. **FIX** failure reconciliation without removing CAS/version retention.

## Bin and local sync

Purge is the most dangerous incomplete storage migration. Current chunks are not selected/enumerated; the cron selects obsolete `userId`, although current objects carry `createdByAccountId` and `spaceId`; missing bucket metadata can still be followed by document deletion. Bulk deletion ignores S3 per-key errors and catches transport failures. **FIX F09** before relying on retention or quota reclamation.

Orphan cleanup protects only live objects; a completed upload whose ledger update failed and was then binned can have its bytes deleted before the 30-day restore window. Prefix listing broadens cleanup beyond explicitly ledgered keys. **FIX F10** with reference checks covering trash, all variants, versions and products.

Local search is RAM MiniSearch populated from encrypted Dexie rows. It is useful local acceleration, but the sync cursor is one unscoped `lastSync` value and the API uses `updatedAt > cursor` with a 1,000-record limit and no tie-breaker. **FIX F20** with a Space/account cursor and durable deletion tombstones. A library with timestamp ties or returning after hard purge can otherwise drift.

## Billing/admin and readiness

Core Razorpay subscription transitions, sanitized BillingEvents, refund processing and organization metering are implemented. Raw Node `crypto` imports for webhook HMAC/idempotency are legitimate; the inspected billing paths do not import file decryption modules. Yet presign/metering code directly downgrades Usage outside `syncUserSubscriptionState` (F21). **FIX** the single-writer contract.

Admin auth is separate from user auth. Its JWT trusts embedded role for eight hours without rechecking an active Admin record, so disabling/deleting/demoting an admin does not invalidate that token (F27). **FIX** revocation/current-role checks.

Drive is feature-rich but not release-ready under the declared invariants. Preserve its working file/sharing/version behavior while addressing authorization, storage lifecycle, key rotation and build topology first.
